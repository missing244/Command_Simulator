Bedrock · Command Context

一条命令，
凭什么知道自己该在哪儿生效？

命令本质上只是一串字。比如"把这一块换成石头"——这句字单独躺着的时候，游戏根本不知道：

谁在说？在哪个世界说？站在哪里说？朝哪边说？

这四个答案合在一起，就是命令上下文。它不是命令的一部分，而是命令执行时身上带着的一张"环境说明书"。

下面从"为什么需要它"讲起，一路讲到"它怎么被改写"。

命令不是凭空生效的：它需要一张写清"谁 / 哪个世界 / 站哪 / 朝哪"的环境说明书。

一 · 为什么要有它

没有参考系，"这里"根本不存在

命令里到处是指代词：~ 是"从这里"、^ 是"朝前"、@s 是"我自己"。

可"这里""前面""我"在游戏里没有固定答案——它取决于这句话是谁、在什么地方说出来的。

看这三块地：同样是"在我脚下放个方块"，起点不同，方块就落在完全不同的地方。同一句话，三个结果，差别只在上下文。

上下文就是那个"参考系"。没有它，命令里的指代词全是悬空的。

上下文不是"额外的设定"，它是命令和世界之间的翻译官。

二 · 执行位置

~ 的原点，就是执行位置

~3 ~2 读作"从这里往东 3 格、往上 2 格"。这个"这里"，就是执行位置。

所以它是个原点：原点不动，~3 ~2 永远指向同一个地方；原点一挪，同样的写法指向的地方就跟着挪。

这也是为什么同一段指令，交给不同的人、不同的方块去执行，落点会变——变的不是指令，是原点。

记住一句话：~ 永远从执行位置出发，而不是从世界原点出发。

执行位置 = 相对坐标的原点。世界不动，原点动。

三 · 执行朝向

^ 的方向，由执行朝向决定

^ ^ ^1 的意思是"向左 0 格，向上 0 格，向前 1 格"。可"前"是哪儿？——它由执行朝向决定。

俯视图里，人一转身，"前"就换方向。所以局部坐标（^）像三根跟着人转的轴：左、上、前。

而世界方向（东南西北）是固定的。灰箭头是世界方向，绿箭头是你的"前"——两者不一定一致，这正是朝向参数存在的意义。

顺带一提：传送、设置出生点这类命令里用 ~ 写"相对朝向"时，基准也是执行朝向。

灰线是世界坐标系方向，绿箭头是"前"。^ 跟着执行朝向转。

四 · 执行者

@s 就是"我自己"

执行者是"谁在下这条命令"。它决定三件事：

· @s 选中谁——就是执行者实体；
· 发消息时显示谁说的——用执行者的名字；
· 很多命令的默认目标——不写目标时，就是执行者自己。

执行者一换，这三件事全部跟着换。所以同一条命令，换个执行者，就像换了个"我"。

注意：命令方块这类执行者没有实体，只有名字，所以它没有"我"可以当目标。

执行者 = 命令的"我"。@s、发言者、默认目标都指向它。

五 · 执行维度

同一个坐标，在三个世界里各有一份

执行维度就是"这句话在哪个世界生效"。坐标 (0, 64, 0) 在主世界、下界、末地各有一份，互不相通。

所以命令只在自己所属的那个世界里动手：选实体的距离范围、方块的位置、找结构的搜索范围，全都在这个维度里算。

换句话说：维度是坐标的"所属世界"。坐标一样，世界不同，结果就是天差地别。

这也是为什么"传送到同一个坐标"有时会跑到另一个世界去——看的是执行维度变没变。

维度 = 坐标的"所属世界"。同一个数字，三个世界各一份。

六 · 合体

一张"上下文身份证"

把四件事写在一张卡上，命令里的指代词就能一一对上：

· as [选择器] → 执行者
· positioned/~/^ → 执行位置
· rotated/facing → 执行朝向（"前"的方向）
· in → 执行维度
· at [选择器] → 执行位置+执行朝向+执行维度

这就是为什么同一串字，在不同卡上会做出不同的事——字没变，卡变了。

读命令时先别急着看参数；先问自己：这张卡上写了什么？

CONTEXT CARD

七 · 深入一点

上下文还能被"换一张卡"

/execute 听起来很玄，其实就一件事：复制现在的卡，改掉其中一格，再拿新卡去跑命令。

比如 as 某人：只换"执行者"这一格，位置/朝向/维度原样保留；再 positioned 坐标：只换"位置"这一格。

每改一格，就得到一张新卡；命令只认最后那张卡。这就是为什么可以"以别人的身份、在别的地方"做同一件事。

基岩版有个细节：/execute 会把维度和朝向当场"定住"（之后不再跟着实体变），而执行者的名字仍然实时跟随执行者实体。

原来那张卡
执行者玩家 A
维度主世界
位置(12,64,36)
朝向(-90°, 0°)
➜
复制
改一格
派生出来的新卡
执行者 玩家 A
维度主世界 定住
位置(12,64,36)
朝向(-90°, 0°) 定住

换"执行者"这一格 → 变成 玩家 B 的身份；再换"位置"一格 → 换到另一个坐标。其它格原样不动。

提示：右卡上带"定住"的格子，表示基岩版里 /execute 执行时就已经固定；执行者名字则一直实时跟随。

八 · 实战

as @a at @a 是怎么"分身"的

一张卡只跑一次命令。as 只换执行者、at 换环境；每命中一个目标，就在父卡下方复制一张新卡。

· as @a：执行者换成每一名玩家 → 2 张卡（环境不变）；
· at @a：环境（维度/位置/朝向）换成每一名玩家的 → 2 × 2 = 4 张卡；
· run：每张卡各跑一次 → 4 次执行。

注意 at @a 会连乘（每人 × 每人）；想"每人只跑一次"就写 at @s ✓

右侧动画：根卡在命令源生成 → 在它下方逐层生成新卡 → 走到叶子执行一次 → 这条分支的卡被删除 → 回到上一层再生成新卡。

例子：命令由 玩家A 执行，两名玩家的环境
玩家 A · 主世界 · 位置 (0, 0, 0) · 朝向 （90°, 0°）
玩家 B · 下界 · 位置 (1, 1, 1) · 朝向 （40°, 0°）
execute as @a at @a run 粒子
① 从命令源生成根卡片… 0 ①②③④

as 决定"以谁的身份"，at 决定"用谁的位置和朝向"；两边各命中几个目标，就乘出几张卡。

九 · 收尾

以后看命令，先问四句话

谁在说？  哪个世界？  站在哪？  朝哪边？

答完这四问，你手里就有一张"上下文卡"。命令里的 @s、~、^、以及所有坐标，都是在这张卡上找答案。

命令负责说"做什么"，
上下文负责回答"在哪里、以谁的身份做"。

内容依据中文 Minecraft Wiki「命令上下文」条目（仅取基岩版：执行者、执行维度、执行位置、执行朝向；其余参数与"不同场景下的上下文"未纳入）。

四问就是上下文。答完，命令自然就"知道"该落在哪里。
