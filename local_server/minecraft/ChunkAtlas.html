01 / 两种区块

一个跟着你跑，
一个钉在原地

加载区块负责“即时计算”，重生点缓存负责“快速热加载”。它们都占内存，但行为完全不同。

重生点缓存

15×15 · 钉在锚点

锚点周围的保留区。它不参与模拟，只把锚点框选范围内“已经加载过”的区块留在内存里，不卸载。重生点缓存让重生、传送回重生点附近时少一次冷加载(磁盘读取)。

  • 形状：15×15 的锚点框
  • 触发：进入世界 / 玩家重生 / 玩家设置重生点
  • 作用：命令可以访问区块内的实体，无法访问/修改方块

03 / 缓存构建

不是预加载，
是“收留已经加载过的”

每个锚点建立一个 15×15 的保留框；框里的区块必须先被加载过，才会进入缓存。

15×15 锚点框
1 / 9
远处：玩家在很远的地方，锚点还没有划定。
加载区 缓存 框内未加载

什么时候触发锚点区域构建？

  • 首次进入世界锚点通常在世界出生点；实测重进世界时会落在进入世界后的玩家位置。
  • 死亡后重生在重生点重新建立锚点视图。
  • 设置重生点床、重生锚、/spawnpoint 都会移动锚点；玩家在很远的地方也可以设置。
  • 关闭世界后重新进入游戏重新建立锚点视图，锚点跟着进入世界时的位置。

然后发生什么？

  1. 在远处设置重生点玩家可以离锚点很远；设置后锚点位置就固定下来。
  2. 划定 15×15 锚点框框只是保留范围，不会主动加载区块。
  3. 玩家靠近，区块先加载青色加载区跟着玩家移动；框外照常加载/卸载。
  4. 框内已加载区块进入缓存没加载过的格子不会凭空出现；它们保持空框。
  5. 玩家离开框内缓存常驻内存；框外旧区块正常卸载。
关键：缓存是“先加载，后收留”。锚点框不会替玩家加载区块；它只决定哪些已加载区块不卸载。

MULTIPLAYER

多个玩家 = 多个锚点框

每个玩家按自己的锚点建立 15×15 缓存。缓存框不会主动加载新区块，只收留已经加载过的；多个玩家就有多个框，重叠区域共用。

04 / 性能代价

缓存的代价：
内存、冻结、选择器

重生点缓存超出模拟距离也不会卸载。它会一直占着内存，并且改变选择器的扫描成本。

SELECTOR SCAN+ 扫描区块
01

内存常驻

只要世界会话还在，缓存区块就会永久常驻——不会因为超出模拟距离而卸载。玩家走远，它仍然留在内存里。

MEMORY / 会话内不释放
02

方块改不了

缓存区块不参与模拟。即使它还在内存里，/setblock、/fill 等修改也不会生效——你看到的是“冻结”的地形。

FROZEN
03

选择器变慢

即使区块不 tick，@e 仍然能选中缓存内的实体。搜索范围越大，扫描的区块越多，选择器越慢。
