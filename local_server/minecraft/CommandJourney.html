COMMAND LIFECYCLE / 01

一条命令，
如何变成一次执行？

命令先是一段文字，然后被拆成词块并检查语法；通过后整理成可复用的执行对象，存进缓存；执行时把它和上下文一起交给执行环节，最后得到反馈或错误。

说明：下面是一套通用的命令处理模型，用来说明“一段文字如何变成一次执行”；不同游戏或框架（包括 Minecraft）的内部实现细节可能不同。

command
setblock 10 64 10 minecraft:stone
文本词块语法生成对象缓存上下文执行反馈

01 / 拆词与语法

先把一句话
拆成可识别的片段

命令不是简单按空格切开。处理流程会根据命令规则识别每一段是什么：命令名、坐标、方块、选择器、数字或文本。

词块：一段文字 + 一个身份

拆词的结果通常是一串“词块”。每个词块除了原文，还知道自己属于哪种参数、在命令里的哪个位置。

→命令名
→三个坐标
→方块
  • 空格不是唯一分隔：选择器、引号文本、JSON 都有自己的切分规则。
  • 类型决定下一步：同样是数字，可能是坐标，也可能是数量或等级。
  • 先识别，不求值：相对坐标、选择器要等执行时才知道具体结果。

语法：只检查“能不能接上”

拆出来的词块要按命令规定的顺序排好。语法检查只关心组合是否合法，不关心方块是否真的存在、目标是否真的在线。

  • 没有执行对象：语法没通过，就不会进入生成执行对象的阶段。
  • 可以为空：有些参数有默认值；有些参数必须显式提供。

02 / 生成执行对象

从“看懂了”
到“可以执行了”

语法通过后，流程会把参数整理成一个执行对象。它不只是原始文字，而是已经知道要做什么、需要哪些参数、哪些要等执行时再结合上下文计算。

执行对象里通常有什么

setblock 执行对象可缓存
动作setblock
原始命令完整保留，方便回显
坐标执行时结合上下文计算
方块已确认存在
模式replace
  • 能提前检查的：方块 ID 是否存在、参数范围是否合理、目标类型是否匹配。
  • 要留到执行的：相对坐标、选择器命中了谁、当前世界状态。
  • 所以能复用：同一个执行对象换一个上下文，仍然可以执行。

编译错误：语法对了，内容不对

命令的形状没问题，但参数在语义上不合法，例如方块不存在、选择器范围矛盾、玩家专用参数用在了非玩家命令上。

语法：✓ 通过 编译：✗ 方块不存在 minecraft:not_a_block 位置：方块参数
  • 停在生成执行对象之前：不会得到可执行的对象。
  • 能定位参数：错误通常能指出是哪一段、哪个范围。
  • 不是运行错误：命令还没有真正开始执行。

03 / 执行对象缓存

同样的命令，
不必每次重新准备

第一次处理一条命令时，拆词、语法和生成执行对象都要做一遍。得到执行对象后，可以把它存起来；下一次同样的命令文本可以直接复用。

缓存里放什么

为了区分“成功”和失败，缓存通常不只有一格：

缓存区放什么
执行对象成功生成的执行对象
语法错误语法检查失败的结果
编译错误生成执行对象失败的原因

错误也可以缓存。同样的错误命令再次进来，可以直接返回上次的结果，不必重新走完整流程。

缓存只保存“做法”，不保存“这一次的情况”

可以把缓存想成一张菜谱：它告诉流程“这道菜怎么做”，但不记录今天是谁下厨、站在哪里、锅里已经有什么。

  • 不保存执行者：同一个执行对象可以交给不同玩家或实体使用。
  • 不保存位置和朝向：相对坐标要等真正执行时才计算。
  • 不保存世界状态：方块、实体、分数在执行时才读取。
缓存：这条命令该怎么做 不缓存：谁执行 · 在哪执行 · 世界现在怎样

所以同一条命令换一个执行者、换一个位置，仍然可以复用同一份执行对象。

04 / 三类错误

错在哪一层，
反馈就长什么样

越早发现的错误，越不需要进入后面的阶段。语法错误停在拆词/语法，编译错误停在生成执行对象，运行问题才发生在执行时。

语法

语法错误

词块排不进命令规则，或者命令还没写完。此时连执行对象都不会生成。

setblock 10 64 → 缺少方块参数 → 流程停止

反馈：指出出错位置和可能缺少的部分。

编译

编译错误

命令形状正确，但参数在语义上不合法，例如未知方块、非法范围、目标类型不匹配。

setblock 10 64 10 minecraft:not_a_block → 方块不存在 → 没有执行对象

反馈：指出出错参数和原因。

运行

运行失败

执行对象已经生成，但执行时没有完成目标操作。流程正常结束，但返回的是失败反馈。

执行对象已生成 → 执行没有完成目标 → 返回失败反馈

缓存：已经生成的执行对象通常仍然保留。

05 / 执行与反馈

执行对象 + 上下文
→ 执行反馈

执行对象只说明“准备怎么做”；上下文告诉它“谁、在哪、朝哪做”；世界提供实际状态。执行完成后，反馈把结果带回调用者。

上下文通常包含

谁在执行：玩家 / 实体 / 服务器 在哪个维度 在什么坐标 朝哪个方向

同一个执行对象换一个上下文，结果可能完全不同。缓存里不保存这些信息。

执行反馈通常包含

成功 / 失败 文字输出 附加数据(实体数/命令结果)

成功和失败都通过反馈返回；调用者根据结果决定下一步。
